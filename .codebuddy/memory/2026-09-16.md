## Operator 握手（Console 401 authentication_required）机制

- 简化流程：浏览器点 Connect → `POST /auth/operator/handoff/request`（claim_token 由页面生成）→ 页面显示 handoff ID → 启动器终端用 `POST /auth/operator/handoff/approve`（bootstrap_token + handoff_id）批准。
- 关键约束（源码 `src/reserving_workflow/api/capabilities.py`）：
  - `approve_bootstrap_handoff` 成功后 `_bootstrap_used = True`，即**每次启动只能批准一次握手**；会话过期后必须重启 workbench 才能重新连接。
  - bootstrap/handoff TTL：启动器设置 `AI_ACTUARY_OPERATOR_BOOTSTRAP_TTL=1800`（30 分钟，handoff ID 有效期内可重试）。
  - operator 会话 TTL 默认 900 秒（15 分钟，`operator_session_ttl_seconds` 上限 3600）。
  - capability 状态全在内存中，不落盘，无法从外部读取 bootstrap token。
- 本次协助方式（第一次）：用 PowerShell `AppActivate(<launcher pid>)` + `System.Windows.Forms.SendKeys` 把 handoff ID 与回车送进启动器窗口 —— **不可靠，未生效**。

## 可靠的握手批准方案（预设凭证 + 接口直接批准）

由于 bootstrap token 随机且只在内存，AI 侧无法自助批准。改为**预设凭证启动**：

```powershell
$env:AI_ACTUARY_OPERATOR_BOOTSTRAP_TOKEN='<>=8位自定义串>'
$env:AI_ACTUARY_OPERATOR_CREDENTIAL='<>=8位自定义串，需与 ADK 凭证不同>'
$env:AI_ACTUARY_OPERATOR_BOOTSTRAP_TTL='1800'
python scripts\run_local_workbench.py
```

然后由 AI 调接口批准（页面显示的 handoff ID 仍需人工提供一次）：

```powershell
Invoke-WebRequest -Uri http://127.0.0.1:8000/auth/operator/handoff/approve -Method POST -ContentType 'application/json' -Headers @{ Origin = 'http://127.0.0.1:8000' } -Body '{"bootstrap_token":"<预设串>","handoff_id":"<页面显示的ID>"}'
```

- 关键：所有 `/auth/operator/*` 写接口都强制校验 `Origin: http://127.0.0.1:8000`，缺头返回 **403 Forbidden**（不是 401）。
- 禁止调 `/auth/operator/bootstrap` 做“连通性探测”，它会置 `_bootstrap_used = True` 从而废掉 handoff 流程；可用 `POST /auth/operator/handoff/request`（带 Origin）无副作用地探测，`expires_in` 可反证 TTL 生效。
- 浏览器端 `claimToken` 只存在 JS 内存里，页面一旦刷新就会丢失并导致 claim 永不成功；页面会按 `expires_in` 每 1 秒轮询 claim，因此批准动作在 TTL 内任何时候做都能被自动领取。

## 排障：控制台 “Create run failed (401 authentication_required)”

- 来源：`app.py` capability 中间件（无 bearer 且无有效 session cookie 时返回 `_safe_auth_error(401, "authentication_required", ...)`）。非匿名路由都要求 principal：浏览器用 operator session cookie，ADK/CLI 用 bearer 凭证。
- 会话只存在 `CapabilityAuthority._sessions`（进程内存）→ **重启工作台即全部失效**；旧 TTL 900s，即使不重启也会掉线。控制台 HTML 本身是匿名的，所以页面照常渲染，只有 API 调用 401（右下角面板是唯一提示）。
- 判断“当前进程里是否已有人领到会话”：`POST /auth/operator/handoff/request` → 200 表示 `_bootstrap_used == False`（还没人领，可继续握手）；401 `bootstrap_invalid` 表示已用过（本进程握手额度已耗尽）。
- `create_bootstrap_handoff` **不会**清掉已有 handoff（只在超过 16 个或过期时拒绝），所以自测探测产生的 handoff 不会顶掉用户的 handoff。
- Bootstrap 窗口 = 进程启动 + 1800s；本次 uvicorn 约 22:26:07 启动 → 窗口 **22:56:05** 关闭。若演示更晚开始，需要在演示前重启 + 重新握手（会话 5 小时从“领取时刻”起算，不是从启动时刻）。

## 排障：控制台 409 review_identity_mismatch（一个坏运行拖垮整个 /console/state）

- 现象：控制台「Experience Study Results / Timeline / Artifact Evidence Panel」全部显示 `Console state failed (409 Conflict) {"code":"review_identity_mismatch"}`。
- 根因（实测）：`tmp/api-artifacts/20260731_demo_run` 被两个运行共用 —— 07-31 的 `operator-20260731_demo_run-20260731T132037685135Z` 与 09-16 22:22:50 的 `operator-20260731_demo_run-20260917T022250313179Z`（**非工具运行的 artifact_root = `api-artifacts/<case_id>`，同名 case 会复用同一目录**）。目录里残留 07-31 的 `review_packet.json`（其 run_id 属于旧运行），新运行加载后 `validate_review_packet_identity` 抛 `ReviewIdentityMismatchError` → 409。
- 放大效应：`GET /console/state`（与 `GET /reviews`）会评估**所有**运行，所以 12 个运行里只要 1 个坏运行，全部请求都 409；用 `GET /runs/{id}/review` 逐个探测可精确定位（本次仅 `operator-20260731_demo_run-20260917T022250313179Z` 为 409）。
- 处置（可回滚）：把冲突的 `review_packet.json` / `review_packet.md` 改名为 `*.stale-20260731.bak`。07-31 旧运行的 review 记录里已内嵌 packet（`record_has_embedded_packet=True`），故其审阅视图仍可用。修复后 `/console/state`、`/reviews`、两个相关 `/runs/{id}/review` 全部 200，`result_panel.status=available`（tool_id=minimax_experience_study_tool）。
- 复发条件：对同一 case_id 重复创建**非工具**运行（共用 `api-artifacts/<case_id>`），目录里若残留别的运行的 review_packet 就会再次 409。根治方案（未实施，待演示后决定）：case 型运行改用 per-run 子目录，或让 `/console/state` 对单个坏运行降级为局部错误。
- 诊断技巧（无需浏览器会话）：从 uvicorn 子进程 env 取 `AI_ACTUARY_OPERATOR_CREDENTIAL`，用 `Authorization: Bearer ...` 直接调控制平面接口：
  `python -c "import psutil;p=psutil.Process(<launcher_pid>);print([c.environ()['AI_ACTUARY_OPERATOR_CREDENTIAL'] for c in p.children(recursive=True) if 'uvicorn' in ' '.join(c.cmdline())][0])"`
- 注意：本机 shell 里 `Get-Content ... -Raw` 不带 `-Encoding` 会被工具安全策略拦截，读 JSON 要写 `-Raw -Encoding UTF8`。
