# ADK Operations Manual

How to configure and use the **ADK Developer Web** surface of AI Actuary, what
it means, and where its guardrails are. [中文版](adk-operations-manual.zh-CN.md)

---

## 1. What this surface is

Google ADK (Agent Development Kit) Developer Web is a **development-only
control-plane assistant** that runs next to the Operator Console:

- It is a chat surface for inspecting the loopback control plane and starting a
  bounded workflow after explicit confirmation.
- It uses the same control-plane APIs as the console, but a **narrower** tool set.
- It never writes business decisions: review decisions, direct tool runs, and
  legacy replay/benchmark endpoints are out of scope.

| | Operator Console (`8000`) | ADK Developer Web (`8001`) |
| --- | --- | --- |
| Audience | actuary / operator | developer |
| Create governed run | yes | only the two published Chainladder workflows |
| Review decision | yes | **no** |
| Report export | yes | debug-only tool, restricted |
| Artifact paths / registry internals | shown | deliberately hidden |

The ADK agent is deliberately not a second source of truth: numbers still come
from the deterministic core, and the console remains the operating surface.

---

## 2. Prerequisites and install

- Python **3.11** (ADK Developer Web is pinned for 3.11)
- `google-adk==2.7.1`
- an `adk` executable next to the interpreter (or on `PATH`)

```bash
pip install -e '.[dev,adk-dev]'
python -c "import importlib.metadata as m; print(m.version('google-adk'))"   # must print 2.7.1
```

Without these the launcher still starts the API/console and reports the ADK
component as unavailable; it never silently degrades the operating surface.

## 3. Start, stop, ports

```bash
python scripts/run_local_workbench.py                 # API 8000 + ADK 8001
python scripts/run_local_workbench.py --disable-adk   # console only
python scripts/run_local_workbench.py --api-port 8123 --adk-port 8124
python scripts/run_local_workbench.py --no-adk-web    # start ADK backend, do not open a browser
```

- ADK Developer Web: `http://127.0.0.1:8001/`
- app endpoints: `/list-apps`, `/apps/ai_actuary_developer/app-info`, `/dev/apps/ai_actuary_developer/build_graph`
- ADK state root: `tmp/adk_work` (per-session subdirectories)
- launcher diagnostics: `tmp/local-workbench-diagnostics/launcher.jsonl`

Cold start takes roughly 30–40 s. The launcher owns both processes (Job Object
on Windows), so closing it stops them; before a manual restart check
`Get-NetTCPConnection -State Listen -LocalPort 8000,8001`.

## 4. Configuration

| Variable | Meaning | Default | Restart? |
| --- | --- | --- | --- |
| `AI_ACTUARY_ADK_MODEL` | model used by the ADK chat agent | `gpt-5.6-luna` | yes (read at import) |
| `AI_ACTUARY_ADK_CREDENTIAL` | capability credential for the ADK execution client | generated by the launcher | yes |
| `AI_ACTUARY_ADK_URL` | loopback URL of ADK Developer Web | `http://127.0.0.1:8001` | yes |
| `DEEPSEEK_API_KEY` | required when the model id starts with `deepseek/` (litellm routing) | — | yes |
| `GOOGLE_API_KEY` | required for Gemini model ids | — | yes |
| `OPENAI_API_KEY` | required for OpenAI-compatible model ids | — | yes |
| `AI_ACTUARY_BROWSER_SMOKE_RUNNER=1` | swap the agent for a model-free deterministic protocol agent used by the browser smoke | unset | yes |

Model id examples:

```bash
AI_ACTUARY_ADK_MODEL=gpt-5.6-luna                 # OpenAI-compatible
AI_ACTUARY_ADK_MODEL=gemini-2.5-flash             # needs GOOGLE_API_KEY
AI_ACTUARY_ADK_MODEL=deepseek/deepseek-flash       # litellm routing, needs DEEPSEEK_API_KEY
```

This is a **separate slot** from the runtime roles described in the
[Operations Manual](operations-manual.md): the ADK chat model never touches a
run result, while `AI_ACTUARY_PLANNER_MODEL` (planner) and
`AI_ACTUARY_REVIEW_MODEL` (reviewer) do.

## 5. What the agent can call

**Read tools (12)**

`get_health`, `get_preflight`, `list_tools`, `get_tool`, `list_workflows`,
`get_workflow`, `list_runs`, `get_run`, `get_run_events`, `get_run_artifacts`,
`get_run_review_snapshot`, `get_artifact_projection`

**Execution tools (4)**

`start_workflow_run`, `wait_run`, `get_run_status`, `summarize_run`

**Debug tools (7)**

`rerun_run`, `replay_run`, `compare_repeatability`, `run_bounded_benchmark`,
`export_run_report`, `get_debug_operation_status`, `wait_debug_operation`

Execution and debug tools work with **trusted run IDs only** and stay inside the
`adk-development` workspace.

---

## 6. Execution rules

- Only two approved workflow ids may be started: `chainladder-basic` and
  `chainladder-validated` (`ALLOWED_ADK_WORKFLOWS`).
- Every start requires **ADK tool confirmation**; the agent must not call it speculatively.
- Each confirmed start carries an **idempotency key**, so a retry cannot create a duplicate run.
- Runs execute in the isolated `adk-development` workspace.
- A poll timeout is **not** a cancellation: the agent must never claim a business run was cancelled.

**Explicitly forbidden** (enforced by the agent instruction): direct tool runs,
legacy path-based replay/benchmark/repeatability/report APIs, submitting review
decisions, and revealing filesystem paths, registry internals, artifact roots,
credentials, secrets, or raw exceptions.

---

## 7. Typical prompts

```text
Is the control plane healthy?
List the published workflows and show the Chainladder workflow.
Start chainladder-basic for case adk-smoke-001 and wait for the result.
Summarize run <run_id> and list its artifacts.
Replay run <run_id> and compare it with <run_id_b>.
```

The agent answers with tool evidence only. If a request falls outside the
approved set, it should say so instead of improvising.

---

## 8. Model-free smoke mode

`AI_ACTUARY_BROWSER_SMOKE_RUNNER=1` replaces the model-backed agent with
`BrowserSmokeAgent`: a deterministic ADK protocol agent that emits the
confirmation event and the workflow call without any model. Use it for the
browser smoke test when no model credential is available.

---

## 9. Diagnostics

| Symptom | Check |
| --- | --- |
| ADK component "unavailable" | `google-adk==2.7.1` installed on Python 3.11, `adk` executable present |
| `incompatible_adk` | reinstall with `pip install -e '.[dev,adk-dev]'` |
| port conflict | launcher refuses occupied ports; pass `--adk-port` |
| agent has no working model | set the matching key for `AI_ACTUARY_ADK_MODEL` |
| want evidence of what happened | `tmp/local-workbench-diagnostics/launcher.jsonl`, `tmp/adk_work/state/...` |
