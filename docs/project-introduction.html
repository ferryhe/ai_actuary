Agentic Actuarial Workbench

AI Actuary 项目介绍与使用指南

AI Actuary 是一个本地优先的精算工作台原型：确定性精算工具负责计算，Agent 负责规划和解释，人类精算师负责判断，所有结果以 artifacts 留痕、可审计、可回放。

一句话：Agents plan and explain; actuarial tools calculate; human actuaries decide; artifacts provide audit and replay evidence.

现在它能做什么

精算计算

内置 Chainladder reserving，当前确定性引擎来自 chainladder-python。

治理审查

生成 constitution check、review packet，并支持独立 review decision。

可审计制品

每次运行写入 run_manifest.json、输入、计算结果、叙述草稿、治理结果和报告制品。

控制面 API

FastAPI 提供 runs、events、tools、workflows、reviews、artifacts、replay、repeatability、batch、report export。

轻量 Console

/console 可以发起任务、轮询事件、查看 evidence panel、处理 review、rerun 和导出 handoff。

工具化接口

七个 CLI/file-artifact 工具组成 actuarial-reserving.v1 合同，可被上层 orchestrator 消费。

架构边界

CAS Core

真值层

schemas、calculators、constitution、replay、benchmark、artifact contract。数值准备金事实必须来自这里。

OpenAI Planner

规划层

把请求转成 bounded plan，负责路由、解释和总结，但不拥有精算真值。

Hermes Workers

执行层

执行任务、打包 artifact、生成 review packet、对接 operator-facing runtime。

边界规则：Run status 只表达执行结果；review decision 是独立治理记录；report export 只从已有证据生成，不补造缺失数值。

安装与启动

安装依赖

git clone git@github.com:ferryhe/ai_actuary.git
cd ai_actuary
python -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'

如果要运行 governed OpenAI planner 路径，需要在本地 shell 或 .env 中提供 OPENAI_API_KEY，不要提交任何密钥。

set -a && [ -f ./.env ] && . ./.env && set +a

启动控制面和 Console

python -m uvicorn \
  'reserving_workflow.api.app:create_app' \
  --factory --host 127.0.0.1 --port 8000
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/health/preflight

浏览器打开：http://127.0.0.1:8000/console

最常用操作

1. 跑一个 governed case
python scripts/run_governed_case.py \
  --case-id demo-case \
  --artifact-dir ./tmp/demo-case \
  --registry-path ./tmp/run-registry.json
2. 触发 review
python scripts/run_governed_case.py \
  --case-id review-case \
  --artifact-dir ./tmp/review-case \
  --registry-path ./tmp/run-registry.json \
  --review-threshold-origin-count 5
3. 查看和 rerun
python scripts/list_runs.py --registry-path ./tmp/run-registry.json
python scripts/show_run.py --registry-path ./tmp/run-registry.json --run-id <run_id>
python scripts/rerun_case.py --registry-path ./tmp/run-registry.json --run-id <run_id> --artifact-dir ./tmp/rerun-case
4. 导出 handoff
python scripts/export_run_report.py \
  --registry-path ./tmp/run-registry.json \
  --run-id <run_id> \
  --review-store-dir ./tmp/reviews

输出：operator_handoff.md、reserve_summary.json、reserve_summary.md。

API 用法

创建同步 run

curl -X POST http://127.0.0.1:8000/runs \
  -H 'content-type: application/json' \
  -d '{
    "case_id": "demo-case",
    "tool_id": "chainladder",
    "inputs": {
      "sample_name": "RAA",
      "method_variant": "chainladder"
    }
  }'

创建后台 run 并轮询

curl -X POST http://127.0.0.1:8000/runs \
  -H 'content-type: application/json' \
  -d '{
    "case_id": "demo-bg",
    "tool_id": "chainladder",
    "inputs": {"sample_name": "RAA", "method_variant": "chainladder"},
    "background": true
  }'

curl http://127.0.0.1:8000/runs/<run_id>/events

Artifact 合同

所有重要事实都落到文件，不靠会话记忆保存。

case_input.json
validated_input.json
deterministic_result.json
narrative_draft.json
constitution_check.json
review_packet.json / review_packet.md
review_decision.json / review_decision.md
operator_handoff.md
reserve_summary.json / reserve_summary.md
run_manifest.json

使用时先读 run_manifest.json。Registry 是操作索引，artifacts 才是审计证据。

下一步建议

  • 定义 artifact retention / persistence，不破坏现有 run_manifest.json 兼容性。
  • 在同一 ToolRegistry / artifact contract 下添加下一个精算工具。
  • 扩充 benchmark case pack，并把 replay / repeatability / report export 纳入 CI 或定期检查。
  • 增加 review packet / handoff report 的 outbound delivery adapter。
  • 生产化 queue、storage、auth、observability 拆成独立 PR，不和工具扩展混做。
